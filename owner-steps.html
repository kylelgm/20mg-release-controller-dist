Owner-only steps

You can do steps 1–6 now. Step 7 is a hard stop; step 8 waits for final review.

Everything below is clicks, pastes and physical actions. Nothing to run.

  1. 1

    Start a separate server

    • Sign in to your owner-only Hetzner account
    • Create a separate project named Release management
    • Start a new server: Ubuntu 24.04, small x86-64 type
    • Keep the public IPv4 option on
    • Select your owner-only SSH key
    Stay on the creation screen. Do not click Create yet.
  2. 2

    Fill three details, paste, then Create

    Fill your three owner details

    The form is offline and works on your device only. Nothing you type is sent anywhere. It asks for:

    • Approval hostname: a public domain name you own and control (see step 3)
    • Owner SSH public key, without the comment. Public key only, never the private key.
    • Owner source CIDR: the network allowed to reach SSH. Narrow is best: a single IPv4 /32 or IPv6 /128. It must be the network you will connect from.

    Every other install value, download and hash is already fixed. No download access token is needed. The installer checksum is checked automatically, and the download bundle is secret-free. Public distribution location: github.com/kylelgm/20mg-release-controller-dist/releases/tag/enrollment-5e13b7a

    • Download the completed cloud-init.yaml
    • Paste the whole file into the Cloud-init box on the same creation screen from step 1
    • Only then click Create server
    Do not create the server until all three details are filled in. No blank fields, private keys or tokens.
  3. 3

    Point the approval address at the server

    • Copy the new server's IPv4 address from Hetzner
    • In your domain's DNS, set an A record for your chosen hostname to that IPv4
    • Set it DNS-only (no proxy)
    • Use a domain in an account you own, separate from any agent profile
    • Open the hostname with https on your owner phone
    This hostname is permanent for these passkeys. Changing it later needs a fresh owner maintenance.
  4. 4

    Get a ticket and enroll your passkey

    • In your owner-only SSH app, save a connection: user root, the new server IP, your owner private key, from the allowed network
    • Request a terminal. The protected menu opens automatically.
    • Select Fresh first enrollment ticket
    • Copy the ticket by hand into the approval page, then register the passkey on your phone
    • If you need to add a second separate device or security key, reconnect and select Fresh recovery access ticket

    Real Face ID acceptance has not been shown yet.

    Never send a ticket in chat.
  5. 5

    Make a private vault

    In 1Password, create a custom vault named 20MG Release. Leave it empty for now.

    Keep it inaccessible to agent sessions.
  6. 6

    Create a read-only service account

    • Create a 1Password service account with access to only the 20MG Release vault
    • Permission: Read items only
    • Save the once-shown token in owner-only recovery storage
    Agents never see this token. Do not paste it in chat.
  7. 7

    STOP: wait for the reviewed packet

    The enrollment-only installer rejects all production token imports and release operations. Wait for:

    • the remaining provider adapters
    • actual denial tests
    • the iPhone ceremony
    • independent Opus review

    Do not import any token until the coordinator explicitly says the reviewed import-enabled packet is ready. A later reviewed bundle will need owner maintenance; the current server cannot update itself.

    Hard stop. Never send production keys to agents.
  8. 8

    Telegram and GitHub: later

    This is a later owner step. The Telegram bot handle and the read-only GitHub permissions will be delivered after final review.

    • Do not invent values
    • Do not send any tokens now
    Telegram is notify-only and never approves a release.
